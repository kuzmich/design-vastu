# design-vastu.ru

Сайт Анны Ивановой: дизайн интерьера и васту. Генератор [Hugo](https://gohugo.io), редактор контента
[Pages CMS](https://pagescms.org), хостинг GitHub Pages. При каждом коммите в `main` GitHub Actions пересобирает
и публикует сайт.

## Где что лежит

| Путь | Что там |
|---|---|
| `content/_index.md` | главная: направления, преимущества, текст «Что такое Васту» |
| `content/obo-mne.md` | «Обо мне» |
| `content/uslugi/*.md` | услуги (одна услуга — один файл; порядок задаёт `weight`) |
| `content/galereya/*.md` | проекты галереи (`images` — список фото) |
| `content/poleznye-stati/*.md` | статьи |
| `content/contacts.md`, `policy.md`, `agreement.md` | контакты, политика, согласие |
| `data/site.yaml` | имя, телефон, e-mail, мессенджеры, реквизиты (используются на всех страницах) |
| `assets/images/` | все фото; Hugo сам делает из них WebP нужных размеров |
| `layouts/` | шаблоны, `assets/css/main.css` — все стили |
| `.pages.yml` | настройка админки Pages CMS |
| `.github/workflows/hugo.yml` | сборка и публикация |
| `legacy/` | старое зеркало сайта на Megagroup и скрипты для него (только для справки) |

Галерея и «Полезные статьи» появляются в меню, когда в них есть хотя бы один материал.
Если поставить `draft: true`, материал будет черновиком и на сайте не появится.

## Локальный запуск

Нужен Hugo **extended** версии не ниже той, что указана в `HUGO_VERSION` в workflow (0.168.0).

```sh
hugo server                      # http://localhost:1313/, страница обновляется при правках
hugo --gc --minify               # собрать в public/
python3 -m http.server -d public # посмотреть собранный сайт
python3 tools/check.py           # проверить ссылки, картинки и якоря в public/
```

## Публикация на GitHub Pages

1. Создайте репозиторий на GitHub и отправьте туда код (ветка `main`).
2. Settings → Pages → Source: **GitHub Actions**. После первого push сайт соберётся сам (вкладка Actions).
3. Свой домен: Settings → Pages → Custom domain → `design-vastu.ru`. В DNS у регистратора добавьте
   A-записи на `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
   (или CNAME `www` на `<логин>.github.io`), затем включите Enforce HTTPS.
   Без своего домена сайт будет доступен по адресу `https://<логин>.github.io/<репозиторий>/`. Ссылки
   строятся от `baseURL`, который workflow подставляет сам.

## Редактирование через Pages CMS

1. Зайдите на https://app.pagescms.org через GitHub и установите GitHub App Pages CMS на репозиторий.
2. Пригласите автора в разделе Collaborators в самой Pages CMS: приглашение приходит на e-mail,
   аккаунт GitHub автору не нужен. Можно и пригласить её аккаунт GitHub в репозиторий
   (Settings → Collaborators, роль Write).
3. В админке есть разделы «Главная», «Обо мне», «Услуги», «Галерея», «Полезные статьи», «Контакты и реквизиты»,
   «Юридические страницы». Фото загружаются в `assets/images/`.
4. Кнопка «Сохранить» делает коммит, через 1–2 минуты изменения появятся на сайте.

## Заявки

Форм нет, потому что серверу на GitHub Pages некуда их отправлять. Кнопка «Оставить заявку» ведёт к блоку
со ссылками на Telegram, WhatsApp и e-mail из `data/site.yaml`.
